## What was built

| Area | Delivered |
|---|---|
| Local infrastructure | `deploy/compose/compose.yaml`: PostgreSQL 16 (owner/app roles), Valkey 8, RabbitMQ 4.3, SeaweedFS (S3), Keycloak 26.8 (realm as code), Mailpit, plus `api` and `web` containers (`--profile app`). Secrets generated by `scripts/dev-setup.sh` and never committed |
| Backend | Spring Boot 4.1 / Java 21 modular monolith with modules `platform` (kernel), `tenancy`, `identity`, `features`, `audit` and `seed`. Boundaries are verified by Spring Modulith |
| Tenancy | Tenant from the signed `tid` claim only. ACTIVE tenant and ACTIVE account required. `TenantAwareDataSource` sets `app.tenant_id` on every connection borrow. Postgres RLS on every tenant table. App role has no `BYPASSRLS` |
| AuthN/AuthZ | OIDC resource server (issuer, audience, expiry, signature). Code-defined permission catalog. 15 system roles. Tenant- and institution-scoped, time-bounded role assignments. `@authz` checks server-side. Token role claims ignored |
| Errors | RFC 9457 problem details with stable `code`, `traceId` and field errors. No stack traces or parser details leaked. Correlation id on every response |
| Audit | Append-only (UPDATE/DELETE revoked), SHA-256 hash-chained per tenant, written in the business transaction. Denied attempts audited in a separate transaction. Integrity verification API |
| Event delivery | Transactional outbox, then RabbitMQ topic exchange with publisher confirms, `SKIP LOCKED` claiming (multi-replica safe), exponential backoff |
| Feature flags | Catalog of 15 flags (modules, assessment types, AI, integrations). Deployment ceiling, then tenant, then institution (institutions can only narrow). **AI and integrations off by default**. Valkey cache with after-commit eviction. Audited, and changes emit events |
| Infrastructure ports | `ObjectStorage` (S3 API, tenant-prefixed keys, presigned URLs) and `EmailSender` (SMTP) |
| Synthetic data | `scripts/seed.sh`: reproducible tenants/institutions/users/role assignments via the app role under RLS. Refuses to run outside DEVELOPMENT/TEST |
| Frontend | pnpm workspace: `@ivorovi/ui` (tokens with runtime tenant branding; Button, Card, Badge, Field/Input/Select, Switch, ConfirmDialog, DataTable, Pagination, Empty/Error/Alert states, Toasts), `@ivorovi/api-client` (generated from OpenAPI), `@ivorovi/web` (PKCE login, in-memory tokens, permission-driven navigation, dashboard, institutions list/detail, feature configuration, audit log with verification, My access) |
| Web runtime | nginx image with runtime `/config.json`, API reverse proxy, CSP and security headers |
| CI | `.github/workflows/ci.yml`: backend build and tests, frontend lint/type/test/build, OpenAPI and client drift checks, compose-based E2E (smoke and Playwright), Trivy scan |
| Docs | Architecture v0.2, ADR-0001…0005 (incl. code-execution evaluation), runbooks (local dev, configuration), OpenAPI contract `docs/api/openapi.json` |

Everything in "What was built", "Database changes" and "APIs" is **implemented and verified** by the tests
listed. The following are **planned only** and must not be read as delivered: rate limiting, idempotency keys,

## Known issues and limitations

The maintained list is the [known issues register](known-issues.md). Snapshot at Phase 0 completion:

1. **CI not yet executed on GitHub** (criterion 9). The Trivy scan was not run locally either: running a downloaded scanner binary was not permitted in this environment.
2. Every authenticated request performs 3 small indexed queries (tenant, account, grants). A short-TTL principal cache with invalidation on role changes is planned for Phase 1.
3. Audit verification is synchronous and O(n) per tenant. Move to a background job before large tenants exist.
4. The web bundle is a single 635 kB chunk (195 kB gzip). Route-level code splitting is planned for Phase 1.
5. The API jar is 105 MB. It includes Datafaker (dev tooling) and both AWS SDK HTTP clients. Split the seeder into a dev-only artifact and drop the unused HTTP client.
6. Hierarchy is tenant → institution only. Campus, department and program scopes, platform-super-admin cross-tenant operations, and user/role management APIs are Phase 1 scope.
7. Not yet implemented kernel items from the architecture: rate limiting, `Idempotency-Key` support, consumer-side inbox de-duplication helper, outbox retention cleanup, OpenTelemetry trace export.
8. Keycloak runs in `start-dev` mode locally. Production Keycloak configuration, Helm chart, and digest-pinned images are Phase 8.
9. Re-running the seeder with the same `random-seed` fails on duplicate tenant codes (documented).
10. Environment note: this build environment needed a Maven Central mirror (configured outside the repo) because of upstream rate limiting. The repository itself uses Maven Central.
